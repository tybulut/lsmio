# LSMIO Backlog

One bullet per item. Repository paths are relative to its root; other paths are upstream sources (libstdc++, ADIOS2, LevelDB, RocksDB) or benchmark output directories. Line numbers may have drifted.

IDs: one letter per category and a number: `C` LSMIO library, `P` ADIOS2 plugin, `B` benchmarks, `S` build and C++ tests, `T` lsmiotool and bmtool. Each item gives its severity: high (wrong or missing results, hangs, site breakage), medium, low, or feature (feature or design work). IDs with an `H`, `M`, `L` or `F` prefix (e.g. H13, M20) are from the numbering of the former `tools/lsmiotool/ISSUES.md`, of items fixed before it was merged into this file.

Status: `[ ]` open, `[x]` completed. In each category open items come first, completed items at the bottom.

## LSMIO library (manager, clients, stores, POSIX)

- [ ] **C1.** (medium) Memory leak in aggregated (collective-IO) mode: `LSMIOClientMPI::recvCommand` (`lib/manager/client/client_mpi.cpp`) allocates `bufReceived` with `new char[]` and never frees it; `deSerializeCmd` copies out of it. Every reply a client receives (get, meta get, barriers) leaks its full size.
- [ ] **C2.** (medium) LevelDB batching is effectively off for values of 512 bytes or more: `LSMIOStoreLDB::_batchMutation` (`lib/manager/store/store_ldb.cpp`) compares `value.size()` (bytes) with `_maxBatchSize` (`asyncBatchSize`, a key count, default 512), so such puts go straight to `DB::Put`; `--lsmio-batch-size`/`--lsmio-batch-bytes` do not apply to them.
- [ ] **C3.** (low) `LSMIOClientAdios` (`lib/manager/client/client_adios.cpp`) is never instantiated (`LSMIOManager` only creates `LSMIOClientMPI`), and its `recvCommand` does not match its `sendCommand`: it expects a 3-int size header and receives all three parts into `cmdBuffer`, leaving key and value uninitialized. Remove it or fix it before use.
- [ ] **C4.** (low) Duplicate copy on the native read path: `SSTableManager::readValueAt` (`lib/manager/store/native/SSTableManager.cpp`) preads 128 KiB speculatively into a thread-local buffer, then copies the value into the caller's string. The record length is known from the next index offset (or the footer), so one `preadv` (header into a small buffer, value straight into the string) would read without the copy.
- [ ] **C5.** (low) Dead 128 MiB per native store: `SSTableManager::flushMemtable` (`lib/manager/store/native/SSTableManager.cpp:300-302`) calls `pubsetbuf` with `m_flush_buffer` (`writeBufferSize`, `lib/manager/store/native/StoreNative.cpp`) on a stream that `FilePool` has already opened, and libstdc++'s `basic_filebuf::setbuf` does nothing on an open file (`bits/fstream.tcc:802`, `if (!this->is_open())`). The stream keeps its default `BUFSIZ` (8 KiB) buffer, so each record of 8 KiB or more is its own `writev` (measured: 2,054 `writev` for 2,048 × 64 KB values in `bm_native`), and the 128 MiB `std::vector<char>`, zero-filled at construction and so resident, is never used. `FilePool` opens its files ahead of time on a background thread (`lib/manager/store/native/FilePool.cpp:57-58`, `:192`), so setting the buffer before the open needs one buffer per pooled file or a pool change; serializing the SST into `m_flush_buffer` and writing it in one call needs neither. Either buffered write adds a copy of every value. Drop the buffer, or use it one of those ways; a fix changes LSMIO benchmark results.
- [ ] **C6.** (low) Aggregated mode still copies each value once on the client: `serializeCmd` packs command, key and value into one message for a blocking `MPI_Send` (`lib/manager/client/client.cpp`, `lib/manager/client/client_mpi.cpp`). Sending the value from the caller's memory (an `MPI_Type_create_struct` over `MPI_BOTTOM`, or a header and a value message) would avoid it; the aggregator's copy out of the receive buffer is its one copy into the C0 memtable.
- [ ] **C7.** (low) RocksDB and LevelDB copy every put at least twice and LevelDB cannot return right after its memtable: `DB::Put` copies the value into a `WriteBatch` and then into the memtable (LevelDB `db/db_impl.cc` `DB::Put`, RocksDB `db/db_impl/db_impl_write.cc`), and LevelDB writes its log record on the calling thread (its `WriteOptions` has no switch to turn the log off; LSMIO turns RocksDB's WAL off by default). Inherent to both; the native store copies once into the C0 memtable.
- [ ] **C8.** (low) Using a native store after `close()` dereferences null: `close()` moves a non-empty active memtable into the flush queue and leaves `m_active_memtable` null, so a later `get`, `getPrefix` or put crashes (`lib/manager/store/native/StoreNative.cpp`). Refuse calls after `close()`, or leave an empty memtable in its place.
- [ ] **C9.** (low) A native store whose memtable add threw leaks that memtable, whatever its type (`LSMIOStoreNative::dropActiveMemtable`, `lib/manager/store/native/StoreNative.cpp`): up to `writeBufferSize` per failed store. Only `MemtableBTree` (tlx, no exception guarantee) is unsafe to destroy; the vector and map memtables keep the strong guarantee. An `IMemtable` flag could leak only the B+ tree. The store is unusable after the failure either way.
- [ ] **C10.** (low) `LSMIOManager::putBytes` has no two-argument form taking `gConfigLSMIO.alwaysFlush`, unlike the `put` pairs (`include/lsmio/manager/manager.hpp`).
- [ ] **C11.** (low) `LSMIOManager::cleanup` (`lib/manager/manager.cpp:684-699`) and `LSMIOStream::cleanup` (`lib/posix/posix.cpp:176`) delete the shared manager while another thread may still use it (a pointer from `getManager()`, or an `LSMIOStream` read or write that passed its state check), a use-after-free; needs a reference count or a reader count that cleanup waits for (`plugin-improvements.md`, "Thread support").
- [ ] **C12.** (feature) Native store accepts values larger than the write buffer, up to 2 GiB − 1, following RocksDB's model: an oversized memtable is written as its own SST, and aggregated puts get an `INT_MAX` guard (design: `plugin-improvements.md`, "Later stage", D2).
- [ ] **C13.** (feature) Aggregated mode without a server thread that calls MPI, so it is safe at any MPI thread level: the aggregator handles client commands inside its own calls (e.g. a collective exchange at `EndStep`/`Close`, as BP5's aggregation does); today it needs `MPI_THREAD_MULTIPLE` (`plugin-improvements.md`, "Thread support"); changes aggregated benchmark results.

## Benchmarks (`benchmark/bm_*`)

- [ ] **B1.** (medium) `bm_adios` read bandwidth without the plugin does not time any file read. Its values are single-value strings, which BP5 keeps in metadata (`BP5Serializer::Marshal`). The reader's `Open` reads `md.0` into memory (`BP5Reader::Init` calls `UpdateBuffer`; with one step that is all of it), and `BeginStep` only decodes it. Both run in `readPrepare`, outside the timer in `BMBase::benchRead` (`benchmark/bm_base.cpp`). The timed `Get` copies from the metadata in memory (`GetSingleValueFromMetadata`), so the `adios2`/`adios2-sync` read rows measure in-memory lookups and copies plus the reader's `Close`, with no file reads. The plugin's `Get` reads the LSMIO store inside the timer, so the two are not comparable.
- [ ] **B2.** (low) `bm_adios` gets with `Mode::Deferred` always, and without `--lsmio-always-flush` also puts with it (`_writer.Put(varKey, &value)`, `_reader.Get(varKey, value)`, `benchmark/bm_adios.cpp`): the put's `value` is a loop local destroyed before `PerformPuts`, and the read compares the value right after `Get`, before `PerformGets`. Correct today only because the LSMIO plugin and BP5 copy at Put and return single-value strings at Get (BP5 `strdup`s them in `BP5Serializer::Marshal` and reads them from metadata in `QueueGetSingle`); ADIOS's contract lets another engine read freed memory or return nothing yet. Use `Mode::Sync`, or keep the values alive until `PerformPuts` and call `PerformGets` before comparing.
- [ ] **B3.** (low) `bm_adios --lsmio-always-flush` (the `flush` variant, and the `adios2-sync` and `plugin-sync` backends arms) puts with ADIOS2's by-value `Put(variable, value, Mode::Sync)`, which copies the value before the engine sees it (`core/Engine.tcc`: `const T datumLocal = datum`), while the Deferred put passes a pointer: the Sync runs measure one extra copy per key. Its `Get` stays `Deferred` (`benchmark/bm_adios.cpp`).

## Build and C++ tests

- [ ] **S1.** (low) `CopyOnceTest.NativeStoreBTreeInsertThatThrows` (`test/test_copy_once.cpp`) reaches the inconsistent-tree state with a key set found for tlx 0.6.1; it only asserts that some put threw. Another tlx (node sizes, split logic) could keep it passing without reaching that state. Check `TLX_VERSION`, or search for a reaching key set in the test itself.
- [ ] **S2.** (low) The copy-count test (`test/test_copy_once.cpp`) covers the native store and the manager only: an extra copy reintroduced in `LSMIOStoreRDB/LDB::putBytes` or the plugin's `WriteVariable` would not fail any test (RocksDB's arena allocates in blocks, so its large allocations do not map onto puts). It also sees only copies that allocate on the putting thread, not a `memcpy` into an existing buffer or the flush thread.
- [ ] **S3.** (low) No SOVERSION on the LSMIO libraries (`lib/CMakeLists.txt` sets only `VERSION`): the `LSMIOStore::putBytes` virtual (added mid-vtable) and the `LSMIOClient::sendCommand` signature change (`std::string_view` value) break a program built against older headers silently. Rebuild every consumer (EPOCpp, the benchmarks) after installing, or set a SOVERSION.
