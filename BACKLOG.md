# LSMIO Backlog

- Native store accepts values larger than the write buffer, up to 2 GiB − 1, following RocksDB's model: an oversized memtable is written as its own SST, and aggregated puts get an `INT_MAX` guard (design: `plugin-improvements.md`, "Later stage", D2)
- ADIOS2 plugin reads a selection that spans several ranks' blocks in aggregated mode, with one get per overlapping block; until then a selection must match its stored block exactly (`plugin-improvements.md`, D4)
- Native SST flush ignores its 128 MiB `m_flush_buffer`: `pubsetbuf` (`SSTableManager.cpp:299-301`) is a no-op on the already-open pooled `ofstream` (`FilePool.cpp:192`, libstdc++ `fstream.tcc:802`), so writes go through the ~8 KiB default buffer and each record ≥ 8 KiB is its own `writev` (measured: 2,054 `writev` for 2,048 × 64 KB values in `bm_native`); `FilePool` opens files ahead of time on a background thread (`FilePool.cpp:57-58`), so installing the buffer before `open` needs a buffer per pooled file or a pool change, while serializing the SST into `m_flush_buffer` and writing it in one call does not; the 128 MiB buffer is allocated and zero-filled for every store but never used; a fix changes LSMIO benchmark results
- Aggregated mode without a server thread that calls MPI, so it is safe at any MPI thread level: the aggregator handles client commands inside its own calls (e.g. a collective exchange at `EndStep`/`Close`, as BP5's aggregation does); today it needs `MPI_THREAD_MULTIPLE` (`plugin-improvements.md`, "Thread support"); changes aggregated benchmark results
- `LSMIOManager::cleanup` and `LSMIOStream::cleanup` delete the shared manager while another thread may still use it (a pointer from `getManager()`, or an `LSMIOStream` read or write that passed its state check), a use-after-free; needs a reference count or a reader count that cleanup waits for (`plugin-improvements.md`, "Thread support")
- lsmiotool's reconciler orders a cancelled job's FAILED/TIMEOUT observation against its cancel request by per-second wall-clock timestamps (`evidence.py:290`, tie rule `<=` at `state.py:1157`, likewise 1181/1226/1251/1342), so a job Slurm reports FAILED or TIMEOUT after our `scancel` is recorded FAILED if both land in the same second and CANCELLED otherwise; order them by sequence or causal predecessor instead
- lsmiotool's `ParseMainTest.testParseMainTargetResolutionBenchmarkName` (`test/main/ParseMainTest.py:510`) is not isolated: outside `./lsmiotool test`/ctest (no `LSMIO_ENV=DEV`) it resolves the real site benchmark root, and even under DEV `inferLatestRun` scans `~/.lsmio-dev/benchmark`, `~/scratch/benchmark/ior`, `~/scratch/ior` and `~/ior`, so a later run there breaks it; patch `lsmiotool.lib.main.siteBenchmarkRoots` to `[]` and point `HOME` at the test's temp dir
